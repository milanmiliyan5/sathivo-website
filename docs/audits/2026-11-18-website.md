## Fixes and changes

1. Header notification, chat and request subscriptions now resume after browser Back/Forward cache restoration. Repeated `pageshow` events do not create duplicate channels. Queued work is cancelled on `pagehide`.
2. Header count event bursts are coalesced, with no overlapping fetches and one trailing refresh if data changes during a fetch. Message events refresh chat counts without also querying notification counts. Incoming-request events are filtered to the companion. Realtime badges remain enabled.
3. Integrated the existing manual maintenance work from PR #17, preserving its backend restrictions and work. The dashboard offers Scan System, confirmed Safe Cleanup, measured database bytes/connections, expired counters, and per-browser cleanup history. Ordinary dashboard counters remain manual; Online Now remains live.
4. Added consistent direct-payment disclosure to request, accepted-booking and chat details, homepage FAQ, Terms and Safety. Users choose their own UPI ID, QR code, UPI-linked mobile number or cash. No platform commission/payment processing, refunds or payment protection is promised. No payment gateway or credential collection was added.
5. Checked in the already-deployed `admin-users-list` and `send-booking-email` function sources for reproducibility; these functions were not changed or redeployed.
6. Added queue behavior and header lifecycle regression tests, expanded Edge Function source checks, and a read-only live HTTP/discovery/unauthenticated-access smoke script. Updated entry-point asset versions.

## Security findings and remaining work

- **Leaked-password protection remains disabled** in the provider advisor. Owner should check availability and enable through Supabase Auth settings; this audit did not change plans or costs.
- Two advisor SECURITY DEFINER warnings were inspected. Booking-name lookup and recovery functions contain participant/admin authorization checks. Do not remove required functions merely to hide an advisor warning.
- Six RLS-enabled backend tables have no ordinary-user policies, intentionally denying client access; do not add permissive policies to silence informational warnings.
- Three missing FK-index suggestions remain for `booking_email_delivery_events.target_user_id`, `booking_requests.cancelled_by`, and `nearby_email_queue.recipient_id`. Review workload/query plans before adding indexes; this audit made no speculative schema changes.
- Chat history currently loads ascending messages without explicit history pagination. Long conversations may hit the API row cap; normal chat images also download again during rerenders. These need a separate tested history-window/media lifecycle change before large-scale chat use.
- Header Back/Forward lifecycle is fixed; other page-specific subscriptions still require authenticated browser lifecycle testing.
- A live marketplace bio contained sexually suggestive wording, and other bios advertised boyfriend-style services. **Owner moderation is required before an AdSense resubmission.** This audit did not delete or rewrite member content. Adding policy pages alone cannot certify all user-generated content.
- No 200/300/500-user capacity claim is established. Run a controlled staged load test with disposable authorized accounts and monitor latency, errors, Realtime connections and message limits. Do not interpret database connections as people.
